# C

| | |
|---|---|
| front end | **doxygen** (sqlite3 output) **+ tree-sitter-c** |
| requires | `doxygen` built with sqlite3 support; `gcc` for preprocessor work |
| Doxyfile | optional — one is synthesized when a repo ships none |

C is the language every layer was built against, so it is the only one where all of them are
exercised: call edges from doxygen's own `xrefs` *and* from tree-sitter, macro-composed edges,
function-pointer callbacks, threads, locks and critical sections, shared-key dataflow, Kconfig
gating, and `@req` requirement links.

## Two edge layers, not one

doxygen supplies `xrefs`; tree-sitter supplies the rest. They corroborate rather than duplicate —
`call_edges` stores one row per layer, and the query surface reports the strongest evidence for a
neighbour rather than every row. Corroboration gets *rarer* at scale, not commoner.

## The three things that decide what gets indexed

`INPUT`, `EXCLUDE`/`EXCLUDE_PATTERNS`, and `FILE_PATTERNS` each independently decide scope.
Fixing one fixes nothing — a replaced `INPUT` with a surviving `EXCLUDE_PATTERNS` still drops
whole trees, and the build exits 0 with a plausible count while doing it.

**Index scope is not gate scope and not Doxyfile scope.** A Doxyfile is a *documentation* target
and may cover far less than you want to reason about; honouring its `INPUT` punished a repo for
documenting itself. Precedence is declaration > whole repo, with the Doxyfile kept for `ALIASES`
and `PREDEFINED` and its `INPUT` replaced. Declare `index_scope` in `.clew.yaml` or
`x-clew: index_scope:` in `.doxygen-guard.yaml` to let the two differ.

## Macros are the recurring trap

**A detector that reads `memberdef` is structurally blind to macro-defined functions.** Accessors
generated by a macro produce thousands of call sites and *zero* `memberdef` rows, so an empty
causal layer can be a fact about the detector rather than about the code. Before concluding a
layer is legitimately empty, check whether the detector could see it at all — then declare the
macro prefixes.

Guarded code is the other half: a body behind `#if MY_FEATURE` is invisible unless the macro is
predefined. Declare it:

```yaml
preprocessor:
  predefined: [MY_FEATURE]
  config_header: include/myproject/config.h
```

`config_header` matters as much as `predefined` — without it the index reports the macros as
enabled and an agent concludes the repository ships them on, when the header has them commented
out.

## Declaring conventions

Lock primitives, thread-spawn wrappers, dispatch tables and accessor families are per-repo and are
**read from declarations, never hardcoded**. Run `clew propose` to see, from evidence in your own
tree, what is worth stating. A repo that calls its mutex through a function pointer needs the
`locks:` section — the lexical default cannot see it, and `releases:` is load-bearing, since
without a release token every critical section stays NULL.

## Requirements

`@req` tags work both literally and via an `ALIASES` xrefitem. The id pattern is read from the
repo's own `.doxygen-guard.yaml`, never assumed. A catalog (`requirements.yaml`) is optional
metadata: without one, `req_edges` still populate from tags and only titles and priorities are
missing.
