**Translation path (runtime)**

1. A caller invokes `mbedtls_strerror(ret, buf, buflen)`, defined at `library/error.c:792`. A zero-length buffer returns immediately, and the buffer is zeroed first. A negative `ret` is negated, so the code is handled as a positive value.
2. The high-level bits (`ret & 0xFF80`) go to `mbedtls_high_level_strerr` (`library/error.c:174`). That is a `switch` on the module part of the code, returning strings such as `"CIPHER - Bad input parameters"`. An unknown value becomes `UNKNOWN ERROR CODE (%04X)`.
3. If the high-level part is `MBEDTLS_ERR_SSL_FATAL_ALERT_MESSAGE` (compiled in under `MBEDTLS_SSL_TLS_C`), the function returns early and does not translate the low-level part.
4. The low-level bits (`ret & ~0xFF80`) go to `mbedtls_low_level_strerr` (`library/error.c:537`), a second `switch` that returns strings such as `"ASN1 - Data is invalid"`. If both parts are present, the high-level string is followed by `" : "` and then the low-level string. If fewer than 5 bytes remain after the high-level text, the low-level part is dropped.
5. Every write goes through `mbedtls_snprintf`, so the output is truncated to fit and always NUL-terminated.

The whole file is gated by `MBEDTLS_ERROR_C`. `MBEDTLS_ERROR_STRERROR_DUMMY` is a second gate, and the index shows a second `mbedtls_strerror` candidate at `error.c:867`, which I'd expect to be the dummy variant. I did not confirm that.

**Where the tables come from**

`library/error.c` is not hand-written. The dossier shows it is generated by a CMake custom command (`library/CMakeLists.txt:134`) that runs `scripts/generate_errors.pl`. That script reads the public headers under `include/mbedtls` and the template `scripts/data_files/error.fmt`. Each `case` is wrapped in an `#if defined(MBEDTLS_<MODULE>_C)` block, so only modules compiled into the build appear in the strings.

**Adding a new string**

1. Add the `MBEDTLS_ERR_<MODULE>_<NAME>` define to the module's public header (for example `include/mbedtls/asn1.h`), in that module's code range. The generator picks it up from the headers.
2. Do not edit `library/error.c`. It is regenerated at build time, so a hand edit is overwritten.
3. Rebuild through the normal build path so the generator runs. Check that the new `case` lands under the right module `#if`.
4. Add a test that fails before the change and passes after it (RED first). The dossier shows no covering test for `mbedtls_strerror`, so I can't point to an existing check on the string output.

**What the index can't settle**

The Perl script body, the `error.fmt` template and the header-parsing rules are not indexed. The `.pl` and `.fmt` files have no symbols and no searchable body. So the exact comment or macro format the generator needs for a description string is unconfirmed. Read `scripts/generate_errors.pl` directly before writing a new header define.
