## How Python reaches the engine

Python uses **ctypes**, not pybind11 or cffi. There is no Python extension module. The path is:

```
Python caller
  └─ entropic/hooks.py, streams.py, mcp.py      (Pythonic facades: dict↔JSON, kwargs, keepalive)
      └─ entropic/_bindings.py                  (generated ctypes shim, restype/argtypes pinned)
          └─ entropic/_loader.py → CDLL(librentropic.so)
              └─ include/entropic/entropic.h     (pure C ABI, ENTROPIC_EXPORT)
                  └─ src/facade/entropic.cpp     (C++ engine; exceptions stop here)
```

- **`_loader.py`** finds `librentropic.so` in this order: `$ENTROPIC_LIB`, then `$ENTROPIC_HOME` (nested, then flat layout), then `~/.entropic`, then `ctypes.util.find_library`.
- **`_bindings.py`** is auto-generated by `scripts/gen_bindings.py` from `entropic.h`. Pre-commit runs `gen-bindings --check`, so the committed file can't drift from the header. Every symbol gets an explicit `restype`/`argtypes`.
- **Callbacks** (hooks, token streams, residency, compactor) are `CFUNCTYPE` objects. The Python facades keep them alive in per-handle registries (`hooks._bound`, `streams._observers`). Without that, the GC reaps the trampoline and the next C-side call hits freed memory.
- **Errors** are integer `entropic_error_t` codes plus `entropic_last_error(handle)`. C++ exceptions never cross the `.so` boundary (design rule 6).

## Memory rules that cross the boundary

The rules are written in the header block at `entropic.h:32-37` and on each function's `@par Memory ownership`:

| Direction | Rule | Enforced by |
|---|---|---|
| Engine → caller (`char*` return or out-param) | Caller owns it; free with `entropic_free()` | Doc comment only |
| Engine → caller (`const char*`) | Owned by the handle, valid until the next call on that handle. Do not free. | Doc comment only |
| Caller → engine (buffer the engine will free, e.g. hook `modified_json`) | Must come from `entropic_alloc()` | Convention; `hooks.py` follows it |
| Allocator pairing | `entropic_alloc` = `malloc`, `entropic_free` = `free` (`src/facade/entropic.cpp:1944-1956`) | Implementation |

The reason for `entropic_alloc` is allocator provenance. A pointer the engine will `free()` must come from the same allocator, not from Python's heap.

**What the Python side does today:**
- `hooks.py::_alloc_c_string` and the hook trampoline call `entropic_alloc`, copy the JSON bytes plus a NUL, and write the pointer into `*modified_json`. The engine frees it.
- Hook context arrives as a `c_char_p` and is copied into Python with `string_at` and `json.loads`. The engine keeps ownership of the original.
- No Python code calls `entropic_free` anywhere.

## Problems I found

1. **Owned `char*` returns are bound as `c_char_p` and leak through the Python-level bindings.** `_bindings.py:294` binds `entropic_list_mcp_servers` with `restype=ctypes.c_char_p`. The header says the caller must free it (`entropic.h:1281`). ctypes copies the string into a Python `bytes` object and discards the pointer, so there is no way to call `entropic_free` on it. The generator maps `char*` to `c_char_p` (`scripts/gen_bindings.py:132-133`), so every owned-return function has the same problem, including `entropic_adapter_info`, `entropic_grammar_get`, and `entropic_list_identities`. The out-param forms (`POINTER(c_char_p)`) can recover the raw pointer with `ctypes.cast(..., c_void_p)`, but the wrappers don't do that. I have not run this to confirm the leak. The reading comes from the ctypes semantics and the code.
2. **Doc drift:** `entropic.h:701` and `:812` say to free with `entropic_free_string`. That symbol is not declared in the header, not bound in Python, and not defined in the `.cpp`. The real function is `entropic_free`.
3. **Hook trampoline fragility:** `_trampoline` declares `ctx_ptr` as `c_char_p`, so ctypes already hands it a `bytes` object. It then calls `ctypes.string_at(ctx_ptr)` on that, which works only because `c_void_p.from_param` accepts `bytes`. A declared `c_void_p` argument would be clearer.

## Suggested next steps

- Change the generator so owned `char*` returns map to `c_void_p`, then wrap them in a helper that copies the string and calls `entropic_free` once. That fixes problem 1 for every such function.
- Fix the `entropic_free_string` references in the header (problem 2). Header edits are design-visible, so per the project rules this needs a flag in the commit message.
- Add a unit test that calls one owned-return binding and checks the result is freed. That needs a built `librentropic.so`, which I did not check for in this repo.
