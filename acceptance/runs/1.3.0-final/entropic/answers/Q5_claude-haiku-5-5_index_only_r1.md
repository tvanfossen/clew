Python reaches the engine through a plain `ctypes` binding over the C ABI in `include/entropic/entropic.h`. There is no C++ or pybind layer, and no OOP wrapper: the package exposes flat functions such as `entropic_create`, `entropic_run_streaming` and `entropic_destroy`. The engine is a shared library, `librentropic.so`, which `python/src/entropic/_loader.py` finds through a fixed search order: `$ENTROPIC_LIB`, then `$ENTROPIC_HOME` (nested and flat layouts), then `~/.entropic/`, then the system `ldconfig` cache. If nothing matches, `find()` returns `None` and the CLI tells the user to run `entropic install-engine`. Binding symbols are imported lazily, so the install step can run before the library exists.

The C ABI is the public surface. The `.so` boundary follows the repo's design rules: pure C, opaque handles, no C++ types, and exceptions converted to error codes. `scripts/gen_bindings.py` (run via the `gen_bindings` task in `tasks.py`) parses the header and generates the ctypes declarations, so the Python side tracks the header rather than being hand-maintained. **Memory rules across the boundary** (from the header and the functions I checked):

1. **Engine-allocated returns belong to the caller.** Any `char*` the engine returns transfers ownership. It must be released with `entropic_free()`, which is `free()` in `src/facade/entropic.cpp`. `NULL` is a no-op. Example: `entropic_run(handle, input, &result_json)` requires `entropic_free(*result_json)`, even on the partial-context error path.
2. **Caller-provided buffers the engine will free must come from the engine's allocator.** Hook `modified_json` is the case here: `_build_trampoline` in `python/src/entropic/hooks.py` calls `entropic_alloc()`, and the engine frees the result. Memory from Python's own allocator must never be handed to the engine to free.
3. **`const char*` returns are borrowed.** They are owned by the handle and valid only until the next call on that handle. Copy them out immediately if you need them later.
4. **Input strings are borrowed for the call.** The engine does not keep pointers to `messages_json`, `params_json` or `prompt` after the call returns, per the interface headers.
5. **Callbacks need their Python objects kept alive.** `register_hooks` stores each trampoline in a per-handle list so it survives as long as the handle does. If the trampoline is garbage-collected while C still holds the function pointer, the call crashes. Deregistration must match.
6. **Exceptions never cross into C.** The hook trampoline catches every Python exception, prints the traceback, and returns pass-through (`rc = 0`). A hook that raises is silently skipped, which hides failures; that is a real trade-off.
7. **Threading:** each handle is serialized, one call at a time. `entropic_interrupt()` is designed to be callable from another thread, so it must not take the API mutex. Handle creation and destruction must not race other calls on the same handle.
