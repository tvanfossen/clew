**How Python reaches the engine:** through `ctypes`, with no C extension and no cffi. The Python package loads `librentropic.so` at import time and binds each C symbol by hand.

```
Python caller
  └─ entropic/__init__, hooks.py, streams.py, helpers.py
       └─ _bindings.py   (AUTO-GENERATED by scripts/gen_bindings.py from entropic.h)
            └─ _loader.py  find() → ctypes.CDLL(librentropic.so)
                 └─ C ABI: include/entropic/entropic.h  (pure C, ENTROPIC_EXPORT)
                      └─ src/facade/*.cpp  (C++ engine behind the C surface)
```

- **Library discovery** (`_loader.py`): `$ENTROPIC_LIB`, then `$ENTROPIC_HOME` (nested and flat layouts), then `~/.entropic/...`, then `ctypes.util.find_library`. If none resolve, it raises an error telling the user to run `entropic install-engine`.
- **Bindings** (`_bindings.py`): every function goes through `_bind(name, restype, *argtypes)`, which pins `restype` and `argtypes`. Enums, structs and `CFUNCTYPE` callback types are generated alongside. Do not edit this file; `inv gen-bindings --check` runs in pre-commit and fails on drift.
- **Opaque handle**: `entropic_handle_t = c_void_p`. Python passes it through unchanged.
- **Callbacks** (`hooks.py`, `streams.py`): Python functions are wrapped in `CFUNCTYPE` trampolines. The trampoline decodes the C arguments, calls the user function, and catches every exception so none escape into C.

**Memory rules that cross the boundary**

The header states the contract (`entropic.h` lines 32–36 and 238–249):

1. Any `char*` return transfers ownership to the caller. It must be released with `entropic_free()`, and never with the host `free()`.
2. Strings returned as `const char*` (e.g. `entropic_version`) are static or engine-owned. Do not free them.
3. Buffers the engine will free (such as a hook's `modified_json`) must come from `entropic_alloc()`, so the allocator matches on both sides.
4. Out-params like `char**` (e.g. `entropic_run`'s `result_json`) are caller-owned and must be freed with `entropic_free()`.
5. Callbacks must not let exceptions cross into C, and the Python side must keep each `CFUNCTYPE` object alive as long as C might call it.

How the Python side follows these rules:

- **Callback lifetime is handled correctly.** `hooks.py` keeps trampolines in a per-handle `_bound` registry and `streams.py` keeps them in `_observers`. The `helpers.py` example says to hold delegation callbacks for the engine's lifetime.
- **Exceptions are contained.** Both trampolines wrap the user call in `try/except` and print the traceback. A failing hook returns rc 0 (pass-through).
- **Allocation for engine-freed buffers is correct.** `hooks._alloc_c_string` and the hook trampoline use `entropic_alloc` before `memmove`-ing the JSON in.
- **Token and context strings are copied correctly.** `streams.py` uses `string_at(ptr, length)`, which is correct for tokens that may contain NUL bytes. `helpers.py` does the same for the patch length.

**The gap: Python never frees engine-owned strings.** `entropic_free` is bound in `_bindings.py` but no Python code calls it. The generator maps every `char*` return to `ctypes.c_char_p` (`scripts/gen_bindings.py:133`), and ctypes then copies the result to a Python `bytes` and discards the pointer. The engine buffer is therefore unreachable and leaks. Affected bindings include `entropic_list_mcp_servers`, `entropic_adapter_info` and `entropic_adapter_list`, `entropic_grammar_get`, `entropic_grammar_validate` and `entropic_grammar_list`, `entropic_profile_get` and `entropic_profile_list`, `entropic_list_mcp_keys`, `entropic_serialize_mcp_keys`, `entropic_get_identity_config`, `entropic_list_identities` and `entropic_validation_last_result`. Out-param strings (`POINTER(c_char_p)`, used by `entropic_run`, `entropic_context_get`, `entropic_metrics_json` and others) have the same problem: reading `.value` copies the text, and the original pointer is not kept for `entropic_free`.

I confirmed the `char*` declarations in `entropic.h` and the `c_char_p` restypes in `_bindings.py` (lines 294–344). I did not run a leak check, so the leak is established by reading the code, not by observing it. A fix would generate `c_void_p` restypes for owned `char*` returns and add a Python-side wrapper that copies and then calls `entropic_free`. That change belongs in `gen_bindings.py`, which is the source of truth.
