**Short answer:** the string comes from a generated lookup table in `library/error.c`. A contributor adds a code by adding a documented `#define` to the module's header and regenerating that file. Nothing in `error.c` is hand-edited.

## Path from a negative return to text

```
caller gets ret = -0x4F80 + 0x0002  (e.g. -0x4F82)
  │
  ▼
mbedtls_strerror(ret, buf, buflen)          library/error.c:792
  │  buflen==0 → return; memset(buf,0)
  │  ret = -ret                              (sign dropped)
  │
  ├─ ret & 0xFF80 ≠ 0 ?  (high-level part)
  │     mbedtls_high_level_strerr(ret)      → "ECP - ..."  or "UNKNOWN ERROR CODE (xxxx)"
  │     if SSL fatal alert (-0x7780): stop here, skip low-level
  │
  ├─ use_ret = ret & ~0xFF80 ; 0 → done
  │
  ├─ buf already has text? append " : " (only if ≥5 bytes remain)
  │
  └─ mbedtls_low_level_strerr(ret)          → "ERROR - ..." or "UNKNOWN ERROR CODE (xxxx)"
```

Result for `-0x4F82`: `ECP - <high-level text> : <low-level text>`.

Key points:

- **Public entry:** `mbedtls_strerror` is declared in `include/mbedtls/error.h:165`. Its only callees are the two lookup functions.
- **Lookup functions:** `mbedtls_high_level_strerr` masks with `0xFF80`; `mbedtls_low_level_strerr` masks with `~0xFF80`. Both are `switch` statements over `case -(MBEDTLS_ERR_X):` returning `"MODULE - description"`.
- **Layout:** `error.h` defines the 16-bit layout: 3 bits of high-level module ID, 5 bits of module-specific code, 7 bits of low-level code. Low-level codes are in 0x0001–0x007F.
- **Disabled build:** if `MBEDTLS_ERROR_C` is off, the `#else` branch at `error.c:867` returns an empty string.

## Where the tables come from

`library/error.c` is generated by `scripts/generate_errors.pl` from `scripts/data_files/error.fmt`, which holds the skeleton with `HEADER_INCLUDED`, `HIGH_LEVEL_CODE_CHECKS` and `LOW_LEVEL_CODE_CHECKS` placeholders. The generator:

1. Scans `include/mbedtls/*.h` for `#define MBEDTLS_ERR_\w+ -0x....` lines with an attached doxygen comment, before or after the define.
2. Dies on a duplicate numeric code, on a definition with no description, or on a definition with both a before and an after description.
3. Maps the name prefix to a module. The module must appear in `@low_level_modules` or `@high_level_modules` in the script; otherwise it exits with "Do not know how to handle".
4. Emits `#if defined(MBEDTLS_X_C)` guards and `#include "mbedtls/x.h"` lines, then one `case` per code.

Regeneration is wired into `library/Makefile:355` and `library/CMakeLists.txt`, so `error.c` rebuilds when a header changes. CI verifies the committed file with `tests/scripts/check-generated-files.sh:135`, which regenerates and diffs.

## Adding a new error code

1. **Pick a free value** in the module's range. Check the comment block in `include/mbedtls/error.h` and the existing `#define`s in the module header. Duplicates are rejected.
2. **Add the define** in `include/mbedtls/<module>.h`, with a doxygen description:
   ```c
   /** Describe the failure in one sentence. */
   #define MBEDTLS_ERR_MOD_NEW_THING    -0x0042
   ```
   The description becomes the human-readable text, so write it for end users.
3. **If the module is new** (no `MBEDTLS_ERR_<MOD>_*` codes exist yet), add its name to `@low_level_modules` or `@high_level_modules` in `scripts/generate_errors.pl`. Assigning a new high-level module also means reserving a 0xFF80-range ID in `error.h`. Also add the `#include` handling if the header's `#if` guard needs a new `MBEDTLS_<MOD>_C` dependency.
4. **Regenerate**: run `make` in `library/`, or `perl scripts/generate_errors.pl` from the repo root. Commit the regenerated `library/error.c` with the header change.
5. **Verify** with `tests/scripts/check-generated-files.sh`, and run the repo's pre-commit gate via `.venv/bin/pre-commit run --all-files` if the checkout has the venv set up.
6. **Changelog:** `ChangeLog.d/00README.md` asks for an entry for user-visible changes, and a new error code is one.
