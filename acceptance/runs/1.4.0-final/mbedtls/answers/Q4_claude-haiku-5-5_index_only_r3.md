The path is a lookup table, and contributors add to it by regenerating `library/error.c`, not by hand-editing it.

**Runtime path (what a caller hits)**

```
int ret  (e.g. -0x0010)
   │
   ▼
mbedtls_strerror(ret, buf, buflen)        library/error.c:792   (public decl: include/mbedtls/error.h:165)
   │  - zero buf, buflen==0 returns early
   │  - ret = -ret  (normalise to positive)
   │  - split on bit masks:
   │      high = ret & 0xFF80   ──►  mbedtls_high_level_strerr(ret)   library/error.c:174
   │      low  = ret & ~0xFF80  ──►  mbedtls_low_level_strerr(ret)    library/error.c:537
   │  - high string written to buf; if low is non-zero,
   │    append " : " and the low string
   │  - unknown code → "UNKNOWN ERROR CODE (%04X)"
   ▼
buf holds e.g. "SSL - ... : ..." (always NUL-terminated, truncated if needed)
```

Details that matter when you read it:

- **Sign is discarded.** Both helpers and `mbedtls_strerror` negate negative inputs, so callers get the same string for `ret` and `-ret`.
- **Two-level code space.** The high-level part (module-level errors like `CIPHER`, `DHM`, `ECP`) is the bits under `0xFF80`. The low-level part (the specific failure within a module, like `ASN1 - Out of data…`) is everything else. Both are case-matched against `-(MBEDTLS_ERR_…)` constants.
- **Fatal SSL alerts short-circuit.** If the high-level part is `-(MBEDTLS_ERR_SSL_FATAL_ALERT_MESSAGE)`, the low-level lookup is skipped.
- **Each module's cases are gated.** Both `mbedtls_high_level_strerr` and `mbedtls_low_level_strerr` wrap each module's cases in `#if defined(MBEDTLS_xxx_C)`, so a string exists only when its module is compiled in. The whole file is gated by `MBEDTLS_ERROR_C`.
- **A second `mbedtls_strerror` exists at `library/error.c:867`,** under the `MBEDTLS_ERROR_STRERROR_DUMMY` gate (`configs/config-symmetric-only.h:26`, `include/mbedtls/mbedtls_config.h:1170`). I did not read its body, so I can't say what it returns; presumably it is the build variant with no string table. The index also reports `mbedtls_strerror` as a single function at `error.c:792`, which is what the callers use.

**Adding a new string**

1. Define the new `MBEDTLS_ERR_<MODULE>_<NAME>` constant in the owning module's header, with a value in the right bit range (high or low).
2. Don't hand-edit the switch blocks in `library/error.c`. They sit between `/* Begin Auto-Generated Code. */` and the end of the table, and are generated by `scripts/generate_errors.pl`. Its usage is `generate_errors.pl include_dir data_dir error_file`. The README section "Generated source files in the development branch" says these generated files must be regenerated with the listed tools, so the generator's input data (`data_dir`) is where the new entry goes.
3. Regenerate `error.c` through `pre-commit`/the project's normal workflow, and check the new case appears under the module's `#if defined(MBEDTLS_xxx_C)` block.
4. Make sure the module's gate is correct for where the constant is used.
