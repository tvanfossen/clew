**How far it reaches into entropic's source:** The dependency stays inside the inference layer.

- **Backend and adapters (`src/inference/`):** `LlamaCppBackend` (`llama_cpp_backend.h`/`.cpp`) is the main consumer. It derives from the abstract `InferenceBackend` and holds raw `llama_model*`, `llama_context*` and `llama_vocab*` members. It also uses the common-chat parser, the speculative-decoding loop and libmtmd for vision. Other files in the layer call llama.cpp directly: `llama_cpp_sampler.*` (wraps a `llama_sampler` chain), `llama_cpp_tokenizer.*` (forwards to `llama_tokenize`), `adapter_manager.cpp` (`llama_set_adapters_lora`), `speculative_compat.cpp` (`llama_vocab_type`), and `inference_c_api.cpp` (ggml log redirection).
- **Public surface (`include/`):** No llama.cpp type or function appears in the indexed `include/` symbols. The only matches there are entropic's own names: `ggml_logging`, `llama_log_path` in `types/config.h`, and `entropic_inference_log_silence` / `entropic_inference_log_to_file` in `interfaces/i_inference_backend.h`. That fits the design rule of no third-party headers in interface contracts and the C-only `.so` boundary.
- **Tests:** Unit tests under `tests/unit/inference/` define mock `llama_*` functions as link-time overrides, so they run without the real library. The model and vocab-only smoke tests use the real C API.
