## How Python reaches the engine

Python talks to the engine through `ctypes` over a plain C shared library. There is no C extension, pybind, or cffi.

```
python code
  └─ entropic/__init__.py       (PEP 562 lazy imports)
      └─ _bindings.py           generated from include/entropic/entropic.h
          └─ _loader.load()     ctypes.CDLL(librentropic.so)
              └─ C facade (entropic.h) → C++ engine internals
```

- **Library lookup** (`python/src/entropic/_loader.py`): `$ENTROPIC_LIB`, then `$ENTROPIC_HOME` (nested and flat layouts), then `~/.entropic/...`, then `ctypes.util.find_library`.
- **Bindings** (`python/src/entropic/_bindings.py`) are generated by `scripts/gen_bindings.py` from `entropic.h` and the `types/*.h` headers. Every symbol gets explicit `restype` and `argtypes`. Enums map to `IntEnum`, structs to `ctypes.Structure`, and callbacks to `CFUNCTYPE`. The file is marked "do not edit". Pre-commit runs `gen-bindings --check` to catch drift.
- **Handles** are `entropic_handle_t = c_void_p`, opaque to Python.
- **Callbacks** go through trampolines written in Python. `hooks.py` wraps `@hook` functions in `HOOK_CB`, `streams.py` wraps token observers in `STREAM_OBSERVER_CB`, and `helpers.py` wraps delegation and attempt-boundary callbacks.

## Memory rules that cross the boundary

These come from `entropic.h`, `docs/architecture-cpp.md`, and the Python code that follows them.

| Direction | Rule | Where it's applied |
|---|---|---|
| Any | Only C types cross `.so` boundaries. No `std::string`, `std::vector`, or C++ vtables. | Architecture rule 1 |
| Engine → caller | A `char*` return transfers ownership. Free it with `entropic_free()`. | `entropic.h` memory-ownership block |
| Engine → caller | A `const char*` returned from a handle is owned by the handle and valid until the next call on that handle. | `entropic.h` |
| Engine → caller | `entropic_version()` returns a static string. Don't free it. | `entropic.h:171` |
| Caller → engine | Any buffer the engine will free (for example, a hook's `modified_json`) must come from `entropic_alloc()`. | `hooks.py:_alloc_c_string` and the trampoline both do this |
| Engine → callback | Pointers passed into callbacks (`ctx_ptr`, `token_ptr`) are callback-scoped. Copy them before returning. | `hooks.py` uses `string_at`, `streams.py` uses `string_at(ptr, len)` |
| Python → C | A `CFUNCTYPE` object must stay referenced or GC frees the thunk. | Kept alive in `_bound` (hooks) and `_observers` (streams) |
| Errors | Exceptions must never cross into C. Trampolines catch and log them. | Every trampoline has a `try/except` |

Hook semantics: a trampoline that returns `None` passes through (rc 0). A non-`None` return is JSON-encoded, written via `entropic_alloc`, and reported as rc 1, meaning transform or cancel.

## A real defect: owned strings are lost in the bindings

The generator maps every C `char*` return to `ctypes.c_char_p` (`scripts/gen_bindings.py:133`). `c_char_p` restype makes ctypes copy the string into a Python `bytes` and discard the pointer. For functions that transfer ownership, that means the caller has no pointer left to pass to `entropic_free()`. Every call leaks.

Thirteen functions are affected. Each is declared `char*` in `entropic.h` with "caller must free with `entropic_free()`", but bound as `c_char_p` in `_bindings.py`:

- `entropic_list_mcp_servers` (line 294)
- `entropic_adapter_info`, `entropic_adapter_list` (305–306)
- `entropic_grammar_get`, `entropic_grammar_validate`, `entropic_grammar_list` (310–312)
- `entropic_profile_get`, `entropic_profile_list` (315–316)
- `entropic_list_mcp_keys`, `entropic_serialize_mcp_keys` (322, 324)
- `entropic_get_identity_config`, `entropic_list_identities` (332–333)
- `entropic_validation_last_result` (344)

`entropic_version` is the one `c_char_p` return that's correct, because it's static.

I also found that `entropic_run` and its siblings take a `POINTER(c_char_p)` out-param, and nothing in `python/src` calls `entropic_free` except the generated bindings themselves. I did not verify whether `ctypes` accepts the out-param pointer where `entropic_free` expects `c_void_p`, so treat the out-param path as unchecked.

**Suggested fix:** teach the generator to distinguish owned returns from borrowed ones. Bind owned returns with `c_void_p` restype, and add a small helper that copies with `ctypes.string_at`, then calls `entropic_free`. The fix belongs in `gen_bindings.py`, not in the generated file. I haven't changed anything or run a test. The leak is established by reading the code, not by running it.
