## How Python reaches the engine

The Python package is a ctypes shim over the C ABI. There is no pybind11 or CFFI layer.

```
Python code
  └─ entropic/__init__.py  (lazy PEP 562 re-exports)
       └─ entropic/_bindings.py   generated from include/entropic/entropic.h
            └─ ctypes.CDLL(librentropic.so)   loaded by entropic/_loader.py
                 └─ C facade: src/facade/entropic.cpp  (extern "C", ENTROPIC_EXPORT)
```

- **Library discovery** (`_loader.py`): `$ENTROPIC_LIB`, then `$ENTROPIC_HOME` (nested and flat layouts), then `~/.entropic/...`, then `ctypes.util.find_library("rentropic")`. `load()` returns a `ctypes.CDLL`.
- **Bindings** (`_bindings.py`): auto-generated by `scripts/gen_bindings.py` and checked in pre-commit. Each symbol is pinned with `_bind(name, restype, *argtypes)`. Enums, `Structure` types, and `CFUNCTYPE` callback typedefs are generated alongside.
- **Handles** are opaque `c_void_p`. Out-params use `ctypes.byref`.
- **Hand-written facades** (`hooks.py`, `streams.py`, `helpers.py`) add lifetime management and JSON marshalling on top of the raw bindings.

## Memory rules that cross the boundary

The C header (`include/entropic/entropic.h`, "Memory ownership" block) sets three ownership classes.

| Kind | Rule | Python-side obligation |
|---|---|---|
| `char*` return or out-param (`run`, `list_mcp_servers`, `get_identity`, …) | Caller owns it. Free with `entropic_free()`. | Keep the raw pointer and free it. Do not rely on an auto-converted `str`/`bytes`. |
| `const char*` return (e.g. `entropic_version`) | Handle-owned or static. Do not free. | Copy it if it must outlive the next call on that handle. |
| Buffers the engine will free (hook `modified_json`) | Must come from `entropic_alloc()`. | Use `entropic_alloc` plus `memmove`. `hooks.py:_alloc_c_string` and the trampoline do this. |

`entropic_alloc` and `entropic_free` are just `malloc` and `free` (`src/facade/entropic.cpp:1944` and `:1954`). Because they are a matched pair inside the same library, allocator provenance is never mixed.

Other rules that matter:

- **Callbacks must stay referenced.** A `CFUNCTYPE` wrapper that Python garbage-collects leaves the engine calling freed memory. `hooks.py` keeps a per-handle `_bound` registry, `streams.py` keeps `_observers`, and the `helpers.py` example holds `_CB` explicitly.
- **Exceptions never cross.** The hook trampoline catches every exception, prints the traceback, and returns `rc=0` (pass-through). The C side only sees an integer.
- **Ownership is handed back as data, not as errors.** Hooks return `1` to transform or cancel. Ownership of the returned JSON moves to the engine.
- **Stream observers get `(const char*, size_t len)`.** The length is explicit, so Python must decode with the length rather than assume NUL termination.

## Problems I found while reading

1. **`c_char_p` restype drops the pointer, so the string cannot be freed.** `entropic_list_mcp_servers`, `entropic_list_mcp_keys`, `entropic_get_identity_config`, and `entropic_list_identities` are bound with `restype=ctypes.c_char_p` (`_bindings.py:294, 322, 332, 333`). The header says each returns a caller-owned `char*`. ctypes converts the return value to `bytes` and discards the raw pointer, so the documented `entropic_free()` call is impossible and each call leaks. The out-param variants (`POINTER(c_char_p)`) have the same hazard if the code reads `.value` and never keeps the raw pointer. Fix: bind these as `c_void_p`, copy with `string_at`, then call `entropic_free`.
2. **Nothing in the Python package calls `entropic_free`.** A search of `python/src/entropic/*.py` finds no call site. The raw bindings are the only surface, so every ownership rule above is the caller's responsibility today.
3. **Doc drift on `entropic_free_string`.** The header (`entropic.h:701, 812`) and `src/facade/entropic.cpp:4022, 4099` say to free with `entropic_free_string`. That function is not defined anywhere. The real deallocator is `entropic_free`. Only `OLD_NOTES.md` also uses the stale name.
4. **CLAUDE.md is stale about the wrapper location.** It says the auto-generated wrapper lives in `python/entropic_native/`. That directory contains only `py.typed`. The generated bindings are in `python/src/entropic/_bindings.py`.

I did not build or run anything. These findings come from reading the source and index. Finding 1 is the one I would verify with a test that frees a `list_mcp_servers` result and checks for a leak, if you want to confirm it at runtime.
