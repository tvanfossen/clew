A negative return value is never looked up in a table at runtime. The string table is generated at build time, and `mbedtls_strerror()` decodes the code by bit masks.

**Runtime path**

```
mbedtls_xxx() returns e.g. -0x4080
        │
        ▼
mbedtls_strerror(ret, buf, len)          library/error.c:792
  ├─ ret = -ret                          sign stripped
  ├─ ret & 0xFF80  → high-level part    e.g. 0x4080 → RSA
  │     └─ mbedtls_high_level_strerr()  switch over masked code
  ├─ ret & ~0xFF80 → low-level part     e.g. 0x0020 → AES
  │     └─ mbedtls_low_level_strerr()   switch over masked code
  └─ concatenates as "HIGH : LOW"       e.g. "RSA - Bad input parameters to function : AES - Invalid key length"
```

- The 16-bit code is split into a 3-bit high-level module ID (bits 7–15, mask `0xFF80`) and a 7-bit low-level code (mask `0x007F`). See the layout comment in `include/mbedtls/error.h`.
- Each `switch` has `case -(MBEDTLS_ERR_X):` entries that return a literal `"MODULE - description"` string. These sit between `Begin/End Auto-Generated Code` markers in `library/error.c`.
- The high-level lookup returns early for `MBEDTLS_ERR_SSL_FATAL_ALERT_MESSAGE`, so the low-level part is not appended.
- Unknown codes produce `UNKNOWN ERROR CODE (XXXX)`.
- If `MBEDTLS_ERROR_C` is off, you get a dummy version that writes an empty string.
- `programs/util/strerror.c` is a small CLI that calls this function, handy for checking a code by hand.

**How the file gets generated**

`library/error.c` is tracked in git but generated by `scripts/generate_errors.pl`. It reads:
- every `include/mbedtls/*.h`, matching `#define MBEDTLS_ERR_<X> -0x....` with a Doxygen comment before or after,
- the template `scripts/data_files/error.fmt`.

The Makefile, CMake, and `make_generated_files.bat` all run it. `tests/scripts/check-generated-files.sh` regenerates it and fails if the committed copy differs.

**Adding a new error code**

1. Add the define to the module's header, e.g. `include/mbedtls/rsa.h`, using a free value in that module's range. The `error.h` table lists the ranges. Use a negative hex literal, `-0x....`, because the regex does not match decimal.
2. Add exactly one description: a `/** ... */` comment before the define, or a `/*!< ... */` after it. Having both, or neither, is a generator error.
3. Use an existing module prefix. If you add a new module, you must also add it to `@low_level_modules` or `@high_level_modules` in `generate_errors.pl`. Otherwise the script exits with "Do not know how to handle". Also make sure it has a matching `MBEDTLS_<MODULE>_C` config symbol, since the generated `#if defined(...)` guards depend on it.
4. Regenerate with `perl scripts/generate_errors.pl` from the repo root, or run `make` in `library/`. Don't hand-edit `library/error.c`. The check-generated-files script would catch a mismatch.
5. Add a test case to `tests/suites/test_suite_error.data`, e.g. `error_strerror:-0x0020:"AES - Invalid key length"`, with the `depends_on` for the module's config symbol. Run it with the repo's test tooling. Per your CLAUDE.md, go through pre-commit or `invoke` rather than calling the tool directly.

The generator rejects duplicate code values, so a collision with an existing code fails at generation time. I did not run the generator or the tests here. The above is from reading the scripts and the code.
