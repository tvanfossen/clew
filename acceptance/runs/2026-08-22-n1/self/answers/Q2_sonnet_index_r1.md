The distinction lives in `clew/mcp_server/emptiness.py`, and it's earned per-call rather than declared by shape. An empty `search` reply is graded into one of three tiers, computed only after the result comes back zero (so the cost is paid exclusively on the empty path, never the common one):

**1. Definitive.** Earned only when a single token matched nothing *and* `query.unsearched_corpora` — which asks the database whether any corpus `search` doesn't read (right now: markdown/Kconfig prose) holds a row this same query would have matched — also comes back empty. Only then does the reply say "this IS a definitive empty result... do not retry or fall back to guessing." This is full confidence, and it's checkable: the query that produced it is named in the code (`unsearched_corpora`), not asserted by the tool description.

**2. Definitive, but for a different reason (absent corpus, not absent match).** If the index was built without a corpus the query needed — no file-level docs corpus, no ingested markdown — the reply says so explicitly (`_NO_FILE_DOCS` / `_NO_PROSE_CORPUS`) rather than claiming the repository lacks the thing. This is also full confidence, but the claim is "the index can't see there," not "the repo doesn't have it" — and it tells the caller how to fix the index (`index(action='refresh')`) instead of how to fix the query.

**3. Not definitive.** Two sub-cases, both graded down:
- *Unread-corpus hit*: `unsearched_corpora` found rows in a corpus `search` doesn't cover (e.g. the name exists as a typedef, but `search` doesn't index typedefs). The reply names the hit count and corpus and points at `dossier` by name — this is the "I didn't look there" case made concrete and actionable, not just claimed.
- *Over-specified conjunction*: for multi-token queries, `token_hit_counts` runs each token independently; any token with zero independent hits is named as the one that emptied the whole AND-match, with instruction to retry without it.

The confidence budget, in short: **definitive** claims ("do not retry, do not guess") are earned only after the code has actually checked every corpus it could have missed and found nothing there either — never from a single zero-row query alone. Everything short of that full check is worded as *not* definitive, with the specific reason (named corpus, named token) and a concrete next action, because the module's own history (gh#31, #315, #372, #373, #374, #404) is four to five separate incidents of the strong wording being issued from partial evidence and turning out false — an agent that was told "do not retry" when a class, variable, macro, or typedef corpus held the match, and either gave up or fell back to grep. The design rule the file states explicitly: fix the corpus (or the diagnosis), never the sentence — a wording tweak that papers over missing coverage would hedge every honest empty reply to excuse the rare dishonest one.
