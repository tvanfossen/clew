The reply never treats an empty result as an error, and it never presents it as a definitive "no." It separates the two cases by reporting what it searched, not by a yes/no flag. I ran a probe with a nonsense name, `zzqxnonexistentsymbol frobnicate`, and got `count: 0`, `results: []`, plus a `note` that says the result is "NOT an error" and "NOT a definitive negative either."

**What the reply reports, and what each part tells you**

| Field | What it tells you |
|---|---|
| `token_hits` | Per-token counts. A conjunction miss shows which token emptied it. Here both tokens had 0, so each alone would empty the query. |
| `note` | Says which corpora were searched (names, `@brief`, macros, typedefs, classes, config symbols, file docs) and which were not (markdown and Kconfig prose, reached via `corpus='prose'`). |
| `scope` | The indexed file set: 426 files, whole repo, with extensions listed. `not_indexed` lists skipped extensions (`.rs=2`, `.toml=2`, `.sql=1`, no-extension=3, and others). |
| `target` | Which repository answered. Split repos also report `not_searched`. |
| `staleness` | Present only if the index is older than the source. |

**Confidence each answer deserves**

- **"Not in the indexed symbols, in a current index":** strong, but only for the searched units. The probe reply itself says prose was not searched, so a conceptual phrase can still hit there.
- **Multi-token miss:** weak. It only shows the tokens did not co-occur in one unit. Retry with the single most distinctive token before drawing any conclusion.
- **"Not in the repository":** moderate at best. Misses are possible for names generated by macros, names in extensions the index skipped, names spelled differently by different consumers (the MCP instructions warn about this), and anything outside the indexed file set, such as a Makefile or CI config.
- **Anything in `not_indexed`:** no confidence from clew at all. Reading the tree directly is the only way to settle it.

**Practical order when a search comes back empty**

1. Retry with one token.
2. Run `corpus='prose'` if the name might be described in docs.
3. Check `scope.not_indexed` against the kind of file you expected, then grep the filesystem for those files.
4. Only after that call it absent, and say which of the above you covered.
