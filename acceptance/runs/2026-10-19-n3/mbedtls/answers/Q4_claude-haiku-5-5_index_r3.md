**Short answer:** `mbedtls_strerror()` splits the code into a high-level part and a low-level part, looks each part up in a switch statement that is generated from the `MBEDTLS_ERR_*` defines in the headers, and joins the two strings. To add a new message, you add a documented define to a header, then regenerate `library/error.c`. You don't edit the switch by hand.

## Lookup path

```
caller: int ret = -0x4080
   │
   ▼
mbedtls_strerror(ret, buf, buflen)          library/error.c:792
   │  buflen==0 → return; memset(buf,0)
   │  ret = -ret                              → 0x4080
   │
   ├─ ret & 0xFF80 ≠ 0 ?
   │     mbedtls_high_level_strerr(ret)      error.c:174  (switch, generated)
   │     → "RSA - Bad input parameters to function"
   │     (NULL → "UNKNOWN ERROR CODE (XXXX)")
   │     if SSL fatal alert → return early (no low-level part)
   │
   ├─ use_ret = ret & ~0xFF80 ; if 0 → return
   │
   ├─ buf already has text? append " : " and shift buf
   │
   └─ mbedtls_low_level_strerr(ret)          error.c:537  (switch, generated)
         → "AES - Invalid key length"
         (NULL → "UNKNOWN ERROR CODE (XXXX)")
```

- The sign is flipped first. The switch cases are written as `-(MBEDTLS_ERR_…)`, so both sides are positive when compared.
- The 16-bit code is split by mask. Bits `0xFF80` are the high-level module ID, and bits `0x007F` are the low-level code (`include/mbedtls/error.h:17-30`).
- The two lookup functions are public (`include/mbedtls/error.h:180, 195`). Callers that only want one half can use them directly.

A worked example with `-0x4080` (RSA, high-level only): the high-level part is `0x4000` and the low-level part is `0x0080`. Because the low-level part is zero, the buffer ends up as `RSA - Bad input parameters to function`.

## Where the switch comes from

`library/error.c` is generated by `scripts/generate_errors.pl`. The Makefile rule at `library/Makefile:355-360` regenerates it whenever a header changes. The generator does the following:

1. Scans every `include/mbedtls/*.h` for this pattern:
   `[/** doc */] #define MBEDTLS_ERR_<MOD>_<NAME> -0x<hex> [/**< doc */]`
2. Takes the description from exactly one doc comment, before or after the define. Having neither or both is a hard error.
3. Derives the module from the name prefix (`MPI` → `BIGNUM`, `CTR` → `CTR_DRBG`, and so on). It sorts the module into a low-level or high-level list. An unknown module is a hard error.
4. Dies on any duplicate value.
5. Fills `scripts/data_files/error.fmt` with one `case -(NAME): return("MODULE - description");` per code, grouped by module under `#if defined(MBEDTLS_<MOD>_C)`.

`tests/scripts/check-generated-files.sh:135` reruns the generator and diffs the result, so a hand-edited or stale `error.c` fails CI.

## What a contributor does to add one

1. **Define the code** in `include/mbedtls/<module>.h`:
   ```c
   /** Something specific went wrong */
   #define MBEDTLS_ERR_FOO_SOMETHING_BAD   -0x0042
   ```
   Pick an unused value inside that module's allocated range. The layout table in `error.h:37-83` documents the allocations, but the generator does not enforce them.
2. **Use the right module prefix.** If the module is new, add it to `@low_level_modules` or `@high_level_modules` in `scripts/generate_errors.pl:27-33`. Add its allocation to the `error.h` comment table as well.
3. **Write the value with a leading minus and hex digits** (`-0x…`). The regex only matches that form. A decimal or unsigned define is skipped without an error, so the code silently gets no message.
4. **Regenerate**, don't edit by hand: `perl scripts/generate_errors.pl` from the repo root, or `make error.c` in `library/`. The Windows path is `scripts/make_generated_files.bat`.
5. **Add a test row** to `tests/suites/test_suite_error.data`, in the existing format:
   `error_strerror:-0x0042:"FOO - Something bad"`.
6. **Commit both** the header and the regenerated `library/error.c`.

Caveat from reading the code: the generator puts a code into the low-level or high-level switch by module name alone, but `mbedtls_strerror` picks which part to look up by bit mask. A low-level code whose module is listed as high-level would be generated into the wrong switch and never match. Keep the value's bit range consistent with its module.
