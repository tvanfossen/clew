**What it accomplishes:** `MBEDTLS_PRIVATE(member)` is a rename, not access control. In `include/mbedtls/private_access.h:14-18`, unless `MBEDTLS_ALLOW_PRIVATE_ACCESS` is defined, it expands to `private_##member`. The struct declarations use the same macro, so a field such as `mbedtls_ssl_ciphersuite_t`'s `flags` (`include/mbedtls/ssl_ciphersuites.h:455`) is really named `private_flags`. Ordinary user code that writes `ctx->flags` fails to compile, which steers people toward the accessor functions and keeps the field names out of the public contract. Nothing is hidden at the ABI level, and the header comment in `ssl.h:5159-5169` makes clear that code reaching in with `ssl->MBEDTLS_PRIVATE(state)` or the define is doing so at its own risk. The 3.0 migration guide (`docs/3.0-migration-guide.md:74`) says the same thing, noting that such code may break in a future minor release.

**For whom, concretely:** the opt-out is a per-translation-unit `#define`, and it is turned on in these places in this tree:

| Where | How it is enabled | What it means |
|---|---|---|
| All library sources (`library/*.c`) | `library/common.h:132` defines `MBEDTLS_ALLOW_PRIVATE_ACCESS` unconditionally. Every library file includes it before the public headers. | Library code sees the real field names. Maintainers can touch internals freely. The 15 `MBEDTLS_PRIVATE` uses in `library/` (e.g. `ssl_ciphersuites_internal.h`, `ecdh.c`, `x509_crt.c`) are fine because the macro expands to the real name there. |
| `programs/ssl/ssl_server2.c:8` and `ssl_client2.c:8` | Defined at the top of the file, before `ssl_test_lib.h`. | These sample programs read internal state directly. Their accesses compile against the real names, and the define must come before any public header is included. |
| `programs/fuzz/fuzz_dtlsserver.c` | Gets the opt-out indirectly. It includes `common.h` at line 4, before `mbedtls/ssl.h`. | It reads `ssl.MBEDTLS_PRIVATE(next_record_offset)` as the real field. Including `common.h` first is what makes this work. |
| `programs/ssl/ssl_context_info.c` | No opt-out. It does not define the macro and does not include `common.h`. | It spells the fields as `ciphersuite_info->MBEDTLS_PRIVATE(flags)` and so uses the mangled `private_flags` names. The struct uses the same mangling, so it compiles, but it depends on internal layout naming and would break if that naming changed. |

The external-user case is the default. Anyone who includes the public headers without defining the macro gets the `private_` names, which is the intended speed bump. The define is not a build option. Nothing in `CMakeLists` or config sets it, so it is only defined in the source files listed above.

**Caveat:** the opt-out is trivially reachable. Any consumer can define `MBEDTLS_ALLOW_PRIVATE_ACCESS` before including the headers, as the sample programs do. That is a deliberate design choice for the library's own tools, and the comments and migration guide treat it as unsupported.
