A caller passes a negative `int` to `mbedtls_strerror()` (`library/error.c:792`). It becomes text in two table lookups, and the tables are generated, so a new code means adding a header `#define` and regenerating, not editing `error.c`.

**Runtime path**

```
mbedtls_strerror(ret, buf, buflen)            library/error.c:792
 ├─ buflen == 0 → return; else memset buf to 0
 ├─ ret = -ret                                 (codes are stored negated)
 ├─ ret & 0xFF80 ?  (high-level bits set)
 │    └─ mbedtls_high_level_strerr(ret)        library/error.c:174
 │         switch on (ret & 0xFF80), returns "MODULE - description"
 │         NULL → "UNKNOWN ERROR CODE (XXXX)"
 │    └─ if it was the SSL fatal alert, return here (no low-level part)
 ├─ low = ret & ~0xFF80 ; if 0 → done
 ├─ buf already non-empty?  append " : "
 └─ mbedtls_low_level_strerr(ret)              library/error.c:537
      switch on (ret & ~0xFF80), returns "MODULE - description"
      NULL → "UNKNOWN ERROR CODE (XXXX)"
```

So `-0x6300` (`MBEDTLS_ERR_CIPHER_AUTH_FAILED`) gives `CIPHER - Authentication failed (for AEAD modes)`. `-0x0020` gives `AES - Invalid key length`. A combined code such as `-0x40A0` gives `RSA - … : AES - Invalid key length`. `tests/suites/test_suite_error.data` pins these exact strings, including the unknown-code cases.

If `MBEDTLS_ERROR_C` is off, a dummy `mbedtls_strerror` at `error.c:867` just writes an empty string.

**Where the tables come from**

`library/error.c` is generated by `scripts/generate_errors.pl` from the `#define MBEDTLS_ERR_*` lines in `include/mbedtls/*.h` and the template `scripts/data_files/error.fmt`. The generator:

- Matches `#define MBEDTLS_ERR_<X> -0x....` with exactly one Doxygen comment, either `/** */` before or `/*!< */` after. Both or neither is a fatal error.
- Rejects duplicate values.
- Sorts each code into the low-level or high-level list by its module prefix. A module missing from the `@low_level_modules` or `@high_level_modules` lists in the script makes it exit 1 with "Do not know how to handle".
- Emits `case -(MBEDTLS_ERR_…): return "MODULE - description";` wrapped in `#if defined(MBEDTLS_<MODULE>_C)` blocks and adds the matching `#include`.

**To add a new error code**

1. Add `#define MBEDTLS_ERR_<MODULE>_<NAME> -0x....` in the module's public header, with one Doxygen comment and a value that doesn't collide. Pick the high-level range (bits `0xFF80`) or the low-level range (`0x007F`) to match how the module's other codes are laid out.
2. If the module is new to the generator, add it to the low- or high-level list in `scripts/generate_errors.pl`.
3. Regenerate with `make -C library error.c` or the CMake `GEN_FILES` target. Don't hand-edit `error.c`.
4. Add a row to `tests/suites/test_suite_error.data` with the expected string, then run it through the normal test path.
5. Run `tests/scripts/check-generated-files.sh`, which regenerates `error.c` and fails on any diff.
