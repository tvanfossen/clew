Python reaches the engine through plain `ctypes` over the C ABI. There is no pybind11, no Cython, and no C++ crossing. The C header is the contract, and both sides follow the rules it documents.

```
Python code
  └─ entropic/__init__.py   PEP 562 lazy exports (names from _bindings_manifest.py)
      └─ _bindings.py       generated by scripts/gen_bindings.py from include/entropic/entropic.h
          └─ _loader.py     ctypes.CDLL(librentropic.so)  (search order: $ENTROPIC_LIB, ENTROPIC_HOME, ~/.entropic, ldconfig)
              └─ C ABI      extern "C" entropic_* in src/facade/entropic.cpp
                            opaque entropic_handle_t (void*); no C++ types cross
```

- **Binding generation:** `_bindings.py` is generated and marked do-not-edit. `inv gen-bindings --check` runs in pre-commit and fails on drift from the header. Every `ENTROPIC_EXPORT` gets a `_bind(name, restype, *argtypes)` line.
- **Lifetime:** `entropic_create` / `entropic_destroy` manage the handle. Nothing is wrapped in a Python class. `entropic/__init__.py` says so explicitly.

**Memory rules, as the header and the Python side apply them**

1. **Returned `char*` out-params are caller-owned.** `entropic_run(h, input, char** result_json)` and similar calls must be freed with `entropic_free()`. The binding is `entropic_free = _bind("entropic_free", None, c_void_p)`.
2. **Returned `const char*` is handle-owned** and valid only until the next call on that handle. `entropic_validation_last_result` is an example. The static version string is never freed. ctypes copies a `c_char_p` restype into `bytes` immediately, so this is safe as long as you don't keep the pointer.
3. **Buffers the engine will free must come from `entropic_alloc()`.** Hook `modified_json` is the main case. Both `entropic_alloc` and `entropic_free` are `malloc`/`free` inside the same `.so`, so the allocator is consistent. `hooks.py` allocates through `entropic_alloc` and `memmove`s the JSON in.
4. **Callback arguments are engine-owned and valid only during the call.** `context_json`, stream `token_ptr`, and delegation structs must be copied out. The Python trampolines use `ctypes.string_at(...)` to copy them.
5. **CFUNCTYPE trampolines must be kept alive by Python.** If the wrapper is garbage-collected, the next C-side invocation calls freed memory. The code handles this in three places: `hooks._HookEntry.trampoline` and the `hooks._bound` registry, `streams._observers`, and the `helpers.py` example.
6. **Exceptions never cross into C.** Each trampoline catches `Exception`, prints the traceback, and returns a neutral code (hooks return `0`, and observers return nothing).
7. **Threading:** the header marks each function with a threadsafety class. Callbacks may fire from the engine thread or a delegation worker, so they must be thread-safe. Init and destroy must not race other calls on the same handle.

**Problems I found while reading**

- **Raw `entropic_run` leaks unless you keep the pointer.** Out-params are declared as `POINTER(c_char_p)`. Reading `.value` copies the string, and the original allocation is lost unless you save the raw address first, for example with `ctypes.cast(p, c_void_p).value`. The package has no helper for this, and the docs don't warn about it. I haven't run a leak test, so this comes from ctypes semantics, not an observed leak.
- **The header names a function that doesn't exist.** `entropic.h` lines 701 and 812 say "free with `entropic_free_string`". Nothing declares or defines that symbol. The real function is `entropic_free`.
- **`hooks._alloc_c_string` is dead code.** The trampoline repeats its logic inline. That breaks the project's DRY rule.
- **Hook registration may be wrong after handle reuse.** `hooks._bound` is keyed by handle address and never cleared on `entropic_destroy`. If a new handle gets the same address, `register_hooks` will skip binding hooks it already has in that list, so the new handle silently gets none. The only reset is a test-surface function. This is a plausible path, not a reproduced failure.
- **Minor:** if `entropic_alloc` returns NULL in the hook trampoline, the callback still returns `1`. The engine then gets no replacement JSON but is told the hook transformed the data.
