**How it's brought in:** llama.cpp is vendored as a git submodule at `extern/llama.cpp`. The index holds `extern/CMakeLists.txt` but no CMake logic, so I can't confirm the build wiring (add_subdirectory vs. FetchContent) from here. The submodule is established by repo prose: `src/inference/llama_cpp_backend.cpp` says "Pinned against llama.cpp submodule b8420", and `RELEASE_NOTES.md` (v2.9.3) records an `extern/llama.cpp` pin bump from `ac4cddeb` to `b9886`. The file-header pin comment is stale. `extern/` is excluded from the C/C++ quality gates.

**How far it reaches into entropic's source:** deep, but confined to one layer.

- **Direct C API use lives in `src/inference/llama_cpp_*`.** `LlamaCppBackend` (`llama_cpp_backend.h:65`) is the 15% concrete base. It owns `model_`, `ctx_`, and `vocab_` as raw `llama_model*`/`llama_context*`/`llama_vocab*`. It also implements the load/activate/deactivate lifecycle, the decode and speculative loops, the MTP head path, and the state save/restore calls. `LlamaCppSampler`/`LlamaCppSamplerFactory` wrap `llama_sampler` chains, and `LlamaCppTokenizer` wraps `llama_vocab`.
- **Raw pointers leak to library callers, not the public API.** `llama_model_ptr()` and `llama_context_ptr()` are public accessors on the backend, so any code holding a backend can reach llama.cpp types. I found no `llama_` types in `include/entropic/`, which is consistent with the design rule that no C++ or third-party types cross the `.so` boundary. I could not verify that every header is clean.
- **Two places copy llama.cpp source rather than link it.** `include/entropic/inference/speculative_compat.h` re-implements `common_speculative_are_compatible` as a file-private static, copied from `extern/llama.cpp/common/speculative.cpp`. `src/inference/tool_call_markers.h` hard-codes markers that mirror `extern/llama.cpp/common/chat-peg-parser.cpp` lines 442–443. Both will drift on a pin bump unless someone checks them, and the test files note this risk.
- **Tests mock the C API.** `tests/unit/inference/` defines link-time stubs for `llama_adapter_lora_*`, `llama_set_adapters_lora`, `llama_model_*`, and `llama_vocab_*`, so CPU-only unit tests run without a real model. The GPU and model tests use the real library.
- **Vendored deps sit alongside it.** `image_preprocessor.cpp` uses stb_image, which is vendored with llama.cpp for the mtmd path.

**Summary:** llama.cpp is a submodule under `extern/`. Its API is used only inside `src/inference/llama_cpp_*` and is hidden behind the pure-C interface, with two hand-copied fragments and a few raw-pointer accessors as the exceptions. To confirm the build wiring, read `extern/CMakeLists.txt` and the top-level CMake file, which are not in the index.
