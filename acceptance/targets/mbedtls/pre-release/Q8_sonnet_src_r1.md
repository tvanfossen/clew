## Which C is machine-generated, and how to tell

Two different signal types exist — a header comment, or nothing at all (you have to know the file list).

**Files that self-identify as generated** (comment at/near the top):
- `library/ssl_debug_helpers_generated.c:1` — `/* Automatically generated by generate_ssl_debug_helpers.py. DO NOT EDIT. */`
- `programs/psa/psa_constant_names_generated.c:1` — `/* Automatically generated by generate_psa_constant.py. DO NOT EDIT. */`
- `tests/src/psa_test_wrappers.c:1` — `/* Automatically generated by generate_psa_wrappers.py, do not edit! */`
- `library/psa_crypto_driver_wrappers.h:4` and `library/psa_crypto_driver_wrappers_no_static.c:4/46` — `Warning: This file is now auto-generated.`
- `tests/include/test/test_keys.h:2` — "This file was automatically generated from framework/scripts/generate_test_keys.py."
- `tests/include/test/test_certs.h:8` — `/* THIS FILE is generated by \`framework/scripts/generate_test_cert_macros.py\` */`
- `3rdparty/everest/library/Hacl_Curve25519.c:4-6` and sibling files under `3rdparty/everest/library/` — generated by an external tool, KreMLin, from F* source (vendored, not written by Mbed TLS at all)

Two of the naming conventions are a giveaway too: any file ending in `_generated.c`/`_generated.h`, or `..._no_static.c`, is machine output by convention.

**Files that are generated but carry NO marker comment at all** — the only way to know is to consult the build scripts:
- `library/error.c` (no header comment identifying it as generated — checked directly)
- `library/version_features.c` (same — no marker)
- `programs/test/query_config.c` (same — no marker)

The authoritative list of what's generated, and by which script, lives in `tests/scripts/check-generated-files.sh:124-141` — every `check <script> <output-file...>` line names a generated artifact regenerated by `make`/`cmake`/`scripts/make_generated_files.bat`. That script is also the one a colleague should run (`tests/scripts/check-generated-files.sh -u`) to regenerate everything after cloning, per README.md's "Generated source files in the development branch" section.
