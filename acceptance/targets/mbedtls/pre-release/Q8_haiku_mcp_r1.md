### What they will need that is not in front of them

Before a colleague can build and test this repository, they must have the following tools installed:

1. **Git** – required to clone the repository and initialize the Git submodule (`framework/`) which is referenced in `.gitmodules:5` and required by line 11 of `Makefile`

2. **CMake 3.10.2+** or **GNU Make 3.82+** – CMakeLists.txt:21 specifies the minimum CMake version; Makefile:3 defines the PERL variable and expects make. Per README.md:51, CMake 3.10.2 or later is required for CMake builds.

3. **A C99 compiler** – GCC 5.4+, Clang 3.8+, Arm Compiler 6, IAR 8, MSVC 2017+, or equivalent. Referenced in README.md:48.

4. **Python 3.8+** – Required as the interpreter for build and code-generation scripts (README.md:49). The CMakeLists.txt:34-37 finds Python 3 via `find_package(Python3 COMPONENTS Interpreter)` and uses it to invoke scripts like `generate_driver_wrappers.py` (CMakeLists.txt:366).

5. **Perl** – Required to run tests and generate some source files (README.md:50). Referenced in Makefile:3 as `PERL ?= perl` and invoked by scripts like `generate_errors.pl`.

6. **Python packages** – For code generation. README.md:66-70 states: *"To install the necessary packages, run: `python3 -m pip install --user -r scripts/basic.requirements.txt`"*

7. **A host C compiler** (possibly different from the target compiler if cross-compiling) – Required to generate test data. README.md:71-79 explains that `HOSTCC`, `CC`, or `cc` will be searched in that order.

8. **Doxygen 1.8.11+** – Only if they plan to build documentation with `make apidoc` (README.md:24-26).

### Machine-generated C code and how to identify it

mbedtls contains several **automatically generated source files** that differ from hand-written code:

**Identification markers:**

1. **Explicit "auto-generated" or "do not edit" comments** – The most reliable indicator. Examples:
   - `library/ssl_debug_helpers_generated.c:1` contains: `/* Automatically generated by generate_ssl_debug_helpers.py. DO NOT EDIT. */`
   - `library/psa_crypto_driver_wrappers_no_static.c:4-5` contains: `*  Warning: This file is now auto-generated.`

2. **Filename convention** – Files with "_generated" in their name are machine-generated:
   - `library/ssl_debug_helpers_generated.c` (CMakeLists.txt:357-371 generates this via `generate_ssl_debug_helpers.py`)
   - `library/psa_crypto_driver_wrappers.h` and `library/psa_crypto_driver_wrappers_no_static.c` (CMakeLists.txt:357-375 generates these via `generate_driver_wrappers.py`)

3. **Build-time generation scripts** – Generated files are produced by these scripts (all located in `scripts/`):
   - `scripts/generate_errors.pl` → `library/error.c`
   - `scripts/generate_features.pl` → `library/version_features.c`
   - `scripts/generate_driver_wrappers.py` → wrapper headers and implementation files
   - `scripts/generate_ssl_debug_helpers.py` → `library/ssl_debug_helpers_generated.c`
   - `scripts/generate_psa_constants.py` → PSA constants files
   - `scripts/generate_visualc_files.pl` → Visual Studio project files
   - `scripts/generate_tls_handshake_tests.py` → test source files
   - `scripts/generate_query_config.pl` → query configuration files

4. **Conditional generation** – The CMakeLists.txt:74-76 `GEN_FILES` option controls whether these are generated on demand. When the option is ON (default OFF in development), the custom commands starting at line 357 invoke Python and Perl scripts to produce the files.

5. **Location and scope** – Most generated files live in `library/` and `tests/include/test/` (CMakeLists.txt:359-408 show test file generation under the `GEN_FILES` condition). README.md:59-88 documents the entire generation process.

The distinction is significant: hand-written code in mbedtls follows normal development practices, while generated code should never be edited directly—modifications belong in the data files and generator scripts in `scripts/data_files/` and `scripts/`.
