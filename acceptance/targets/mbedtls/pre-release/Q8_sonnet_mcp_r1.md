## What they'll need before running anything

**Toolchain (not currently present in a bare clone):**
- A C99 compiler + linker/archiver (`README.md:48`)
- GNU Make ≥3.82, or CMake ≥3.10.2 if using CMake (`README.md:47,51`)
- **Python 3.8**, plus packages installed via `python3 -m pip install --user -r scripts/basic.requirements.txt` — needed to generate the test code and to integrate PSA drivers (`README.md:49,66-68`)
- **Perl** — to run the tests, and to generate some library source files (`README.md:50,65`)

**A missing git submodule — this is the one most likely to trip them up.** This checkout is tag `v3.6.7`/`mbedtls-3.6.7` (`git log -1`, verified locally), and `.gitmodules` declares a `framework` submodule (mbedtls-framework) whose path (`framework/`) exists but is **empty** — `git submodule status` shows it unpopulated (leading `-`). `README.md:57` says the submodule "is not needed to merely compile the library at a release tag," but `tests/CMakeLists.txt` (e.g. lines 24, 36, 48, 60, and its `mbedtls_framework/*.py` dependencies at 105-110, 137, 157) shows the test-generation targets invoke `../framework/scripts/generate_*.py` directly — so **running the test suite does need it**, release tag or not. They must run `git submodule update --init` (or clone with `--recurse-submodules`) before `make check`/`ctest`.

- Doxygen ≥1.8.11 only if they want to build docs (`README.md:53`)

## Machine-generated C in this repo

Two generated `.c` files are already checked in and can be identified purely by content — each opens with an explicit banner:

- `library/ssl_debug_helpers_generated.c:1` — `/* Automatically generated by generate_ssl_debug_helpers.py. DO NOT EDIT. */`
- `programs/psa/psa_constant_names_generated.c:1` — `/* Automatically generated by generate_psa_constant.py. DO NOT EDIT. */`

Their filenames also carry a `_generated` suffix, but that's not reliable on its own — some generated files don't follow it:

- `tests/src/psa_test_wrappers.c:1` / `tests/include/test/psa_test_wrappers.h:1` — `/* Automatically generated by generate_psa_wrappers.py, do not edit! */`
- `tests/include/test/test_keys.h:1-3` — banner naming `framework/scripts/generate_test_keys.py`
- `library/psa_crypto_driver_wrappers.h:1-4` and `library/psa_crypto_driver_wrappers_no_static.c:1-4` — no `_generated` in the name, banner instead reads `Warning: This file is now auto-generated.` (built from `scripts/generate_driver_wrappers.py` and the Jinja templates under `scripts/data_files/driver_templates/`)

**Beyond what's checked in:** the actual test suite `.c` files (e.g. `test_suite_rsa.c`) don't exist in the tree at all yet — `CONTRIBUTING.md:60` explains they're "dynamically generated to produce the actual test source files" from a `.function` file + a `.data` file under `tests/suites/`, at build time (this is one of the things the missing `framework` submodule blocks).

**Reader's rule of thumb:** don't infer "generated" from the filename — check the first few lines for `Automatically generated by <script>.py` / `Warning: this file is now auto-generated` / `do not edit`. That header consistently names the generating script, which is the reliable signal; the `_generated` suffix is a convention some but not all of these files use.
